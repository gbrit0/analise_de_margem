{% if portal_renovacao_url %} {% comment %} Mantém vivo o cookie do portal (brg_access_token) enquanto a tela está aberta. Sem isto: o access token do Keycloak vale 5 MINUTOS e o nginx (auth_request -> auth_validador) barra a requisição ANTES de o Django ser chamado — a pessoa estava conferindo margem e do nada levava "acesso negado" mesmo tendo permissão. A sessão do Django de pé não ajuda, porque a barreira é anterior a ela. O /auth/refresh é do portal, na mesma origem: troca o refresh_token pelo access token novo e regrava o cookie. 401 dali significa que a sessão acabou de verdade (o Keycloak recusou o refresh) — aí a pessoa volta para o portal, nunca para a tela do Keycloak. Inline de propósito: não depende de arquivo estático versionado, então navegador com JS antigo em cache não fica sem renovação. {% endcomment %} {% endif %}
